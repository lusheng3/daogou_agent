# 项目范围

## 1. 项目目标

构建一个 Java 实现的电商导购 Agent，完成从商品推荐到多轮追问、比较和加购的可演示闭环。

项目用于展示以下能力：

- Workflow 与 ReAct 的分工。
- 短期记忆和长期偏好。
- Query 改写与意图分类。
- 混合检索、重排和来源引用。
- 工具调用、业务校验和幂等写入。
- Trace、单节点测评和端到端回归。

## 2. 面试版 MVP

### 2.1 用户主链路

1. 用户提出带条件的商品推荐请求。
2. 系统读取会话历史和长期偏好。
3. 系统补全省略信息和指代对象。
4. 系统识别业务领域和请求动作。
5. Agent 调用商品或知识检索工具。
6. 系统返回带依据的回答和有序商品卡。
7. 用户围绕商品卡继续追问、比较或加购。
8. 系统持久化消息、展示顺序和操作结果。

### 2.2 必须支持

- 商品推荐。
- 多轮商品指代。
- 商品条件追加和修改。
- 商品比较。
- 加入购物车。
- 无合格商品时说明限制。
- 请求 Trace。
- 固定场景的回归测评。

### 2.3 明确不做

- Android 原生客户端。
- 完整管理后台。
- 订单、支付、退款和售后。
- 图片搜索、语音和 TTS。
- 多 Agent 自主任务转交。
- 复杂 MCP 服务市场。
- 真实生产级风控系统。

上述能力可在后续演进中增加，不进入当前 MVP 验收。

## 3. 核心验收场景

### 场景 A：商品推荐

用户：`推荐一款 500 元以内、适合通勤的耳机，不要入耳式。`

预期：

- 识别为导购推荐。
- 查询商品资料。
- 预算和佩戴方式作为硬条件。
- 返回商品和依据。
- 不推荐超预算或入耳式商品。

### 场景 B：多轮指代

用户：`第二款有黑色吗？`

预期：

- 从历史 `display` 定位第二款商品。
- 不重新理解为当前搜索结果中的第二款。
- 查询对应 SKU、价格和库存。

### 场景 C：商品比较

用户：`这两款哪个更适合跑步？`

预期：

- 明确比较对象。
- 使用同一组维度比较。
- 结论有商品资料依据。

### 场景 D：加购

用户：`把第二款黑色加入购物车，数量 1。`

预期：

- 定位到正确商品和 SKU。
- 生成并复用 `operation_id`。
- 写入数量正确。
- 重试不会重复加购。

### 场景 E：刷新恢复

流式回答结束后刷新页面。

预期：

- 回答内容一致。
- 商品卡顺序一致。
- 购物车状态与服务端一致。

## 4. 非功能目标

- 单次用户请求的 Agent 模型调用最多 3 次。
- 单次商品搜索最多 2 次。
- 每个节点记录输入摘要、输出摘要、耗时和错误信息。
- 所有价格、库存和 SKU 以业务数据库为准。
- 关键检索结论必须保留来源标识。
- 本地开发可在不依赖真实线上环境的情况下运行。

## 5. 技术约束

- Java 21。
- Spring Boot 3.x。
- Maven。
- MySQL 8。
- Redis。
- Milvus。
- REST API。
- SSE 流式输出。

具体版本和基础设施启动方式在 `platform-foundation` Spec 中确定。

## 6. 术语

- `session`：一次连续会话。
- `message`：用户或 Agent 的一条消息。
- `display`：一次回答中展示的有序商品集合。
- `task`：当前用户目标对应的任务状态。
- `operation`：一次加购等业务写操作。
- `claim`：回答中一条可核对的事实。
- `recommendation`：基于 claim 形成的推荐理由。
- `Trace`：一次请求内各节点的执行记录。
